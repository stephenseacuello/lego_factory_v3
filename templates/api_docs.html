Introduction

Welcome to the Flask CNC SCADA API documentation. This API provides comprehensive access to manufacturing execution, machine control, quality management, and analytics capabilities.

Base URL
http://localhost:5000/api
Response Format

All responses are returned in JSON format with consistent structure:

{
  "success": true,
  "data": { ... },
  "message": "Operation completed successfully",
  "timestamp": "2025-01-03T12:00:00Z"
}

Authentication

API endpoints support optional JWT authentication. Include the token in the Authorization header:

Authorization: Bearer <your-jwt-token>
POST /api/auth/login

Authenticate user and receive JWT token

ParameterTypeDescription
username string User's username required
password string User's password required

TinyG Controller

GET /api/tinyg/status Real-time

Get current TinyG controller status including position, state, and configuration.

POST /api/tinyg/command

Send a G-code or JSON command to the TinyG controller.

ParameterTypeDescription
command string G-code command (e.g., "G0 X10 Y20") required
POST /api/tinyg/home

Execute homing cycle on specified axes.

POST /api/tinyg/feedhold

Pause current motion with feedhold command.

POST /api/tinyg/resume

Resume motion after feedhold.

Work Orders

GET /api/workorders/

List all work orders with optional filtering and pagination.

ParameterTypeDescription
status string Filter by status (pending, in_progress, completed)
limit integer Number of results (default: 50)
offset integer Pagination offset (default: 0)
POST /api/workorders/

Create a new work order.

{
  "wo_number": "WO-2025-001",
  "part_number": "PART-001",
  "quantity_ordered": 100,
  "priority": "high",
  "due_date": "2025-01-15"
}
GET /api/workorders/{wo_id}

Get details of a specific work order.

PUT /api/workorders/{wo_id}/status

Update work order status.

Labor Tracking

GET /api/labor/who-is-working

Get list of operators currently clocked in and working.

POST /api/labor/clock-in

Clock an operator into a work order operation.

POST /api/labor/clock-out

Clock an operator out of their current operation.

OEE Metrics

GET /api/oee/current Real-time

Get current OEE metrics for all machines.

GET /api/oee/machine/{machine_id}

Get OEE metrics for a specific machine.

GET /api/oee/trends

Get OEE trend data over time.

ParameterTypeDescription
period string Time period (hourly, daily, weekly, monthly)
days integer Number of days to include (default: 7)

Downtime Tracking

GET /api/downtime/machines/down Real-time

Get list of machines currently down.

POST /api/downtime/events

Record a new downtime event.

GET /api/downtime/pareto

Get Pareto analysis of downtime reasons.

Sensors

GET /api/sensors/status Real-time

Get current status of all connected sensors.

GET /api/sensors/data

Get latest sensor readings.

Genealogy & Traceability

GET /api/genealogy/analytics/summary

Get genealogy analytics summary.

GET /api/genealogy/serial/{serial_number}

Trace component history by serial number.

POST /api/genealogy/record

Record a genealogy relationship.

Dispatching

GET /api/dispatching/queue

Get current job dispatch queue.

POST /api/dispatching/dispatch

Dispatch a job to a machine/operator.

MCP Integration

GET /api/mcp/tools

List available MCP tools.

POST /api/mcp/execute

Execute an MCP tool.

Error Handling

All API errors follow a consistent format:

{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Invalid parameter: quantity must be positive",
    "details": { ... }
  },
  "timestamp": "2025-01-03T12:00:00Z"
}
HTTP Status Codes
CodeMeaning
200Success
201Created
400Bad Request - Invalid parameters
401Unauthorized - Authentication required
404Not Found - Resource doesn't exist
500Server Error - Internal error
